# Obake Design Handbook

**設計手法を理解し、選び、実践するためのハンドブック**

Obake Design Handbook は、ソフトウェアの設計手法を初めて学ぶ人にも分かるように説明する文書リポジトリです。一般的な手法も、独自に考案された手法も扱います。

このハンドブックの目的は、読者が**自分のプロジェクトの課題に合う手法を選び、実際の設計や実装に使えるようになること**です。特定の手法を、すべてのプロジェクトにとっての正解として勧めるものではありません。

## どこから読むか

- **使う手法を決めたい** → [設計手法の選び方](guides/selection.md)
- **個別の手法を知りたい** → [設計手法の一覧](methods/README.md)
- **複数の手法を一緒に使いたい** → [設計手法の組み合わせ方](guides/combinations.md)
- **似た手法の違いを知りたい** → [手法の比較](comparisons/README.md)

## 文書の構成

- [`methods/`](methods/README.md)：個別の設計手法の説明、適用方法、向き不向き
- [`guides/`](guides/README.md)：手法の選び方、組み合わせ方
- [`comparisons/`](comparisons/README.md)：複数の手法の違いと使い分け

各文書には、関連するページへのリンクと、元の一覧へ戻るリンクを置きます。特別なサイト生成ツールを使わず、GitHub 上の Markdown だけで読み進められる構成にします。

## 解説の方針

1. **初めて読む人にも伝わる日本語で書く。** 専門用語は初めに説明し、必要に応じて具体例を添えます。
2. **「何か」だけでなく「なぜ必要か」を説明する。** 背景、目的、基本的な仕組みを分かるようにします。
3. **採用しない理由も示す。** 利点だけでなく、導入時に必要な作業や、向いていない状況を具体的に説明します。
4. **実践できる説明にする。** 手順や例を通して、自分のプロジェクトに当てはめる方法を示します。
5. **出典と補助ツールを区別する。** 詳しい仕様やツールが別にある場合も、基本的な理解は本文だけでできるようにします。

各設計手法の詳細な実装や補助ツールは、原則として元のリポジトリで管理します。
